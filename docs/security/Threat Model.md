# Threat model

This is a pragmatic threat model for the controlled beta. It prioritizes likely
abuse of the architecture that exists today, not hypothetical future payments,
ads, or enabled push/history features. Status terms are defined in
[Security.md](./Security.md).

## Assets and trust assumptions

- Learner identity, progress, profile, social/league state, optional saved AI
  text, and profile images are the primary user assets
  (`supabase/migrations/20260611232000_user_tables.sql`;
  `supabase/migrations/20260921192802_profile_follows.sql`;
  `supabase/migrations/20261008120000_ai_conversation_history.sql`).
- The Supabase service-role key, Anthropic key, Apple signing key, cron secret,
  and Sentry upload token are privileged server/build secrets. The repository
  documents that they must not be `VITE_` variables
  (`api/_lib/supabase.js:5-15`; `.env.example`; `vite.config.js:18-22`).
- Vercel server functions are trusted to map authenticated callers to their own
  user IDs before using the service role
  (`api/_lib/auth-middleware.js:18-31`;
  `api/_lib/accountHandler.js:76-129`).

## Abuse cases to keep in regression coverage

1. Authenticate as A and attempt every CRUD verb against B's rows and object
   namespace (`supabase/tests/rls/policies.test.js:1-157`;
   `supabase/tests/rls/storage.test.js:90-159`).
2. Supply `user_id`, `isAdmin`, role metadata, another avatar path, or another
   conversation ID and confirm the server ignores/rejects it
   (`api/v1/account/profile.test.js:47-113`, `:285-325`;
   `api/_lib/accountHandler.test.js:315-365`).
3. Exercise an unlisted verified email across account, progress, league, AI,
   export, and deletion, then verify the owner can remove any Auth/profile row
   created before the gate (`docs/PRE_BETA_OWNER_CHECKLIST.md:112-137`).
4. Exhaust burst and daily AI limits, simulate Supabase quota-store failure, and
   compare `shadow` versus `enforce` outcomes
   (`api/_lib/ratelimit.test.js`; `api/_lib/aiQuota.test.js`;
   `api/_lib/handler.test.js`).
5. Delete a fully populated throwaway account and prove zero linked database
   rows, no avatar objects, no Apple authorization, and no sign-in session remain
   (`supabase/tests/rls/cascade.test.js`;
   `api/v1/account/delete.test.js:226-395`;
   `docs/AUTH_APPLE_OAUTH_RUNBOOK.md:82-95`).
